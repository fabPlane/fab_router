# Scenario: fanout gives SMD Pads an escape

_generated by running both baseline routers as sealed programs on the board with the stated settings and recording what each produced: the fanout stage alone (`fanoutEnabled: true`, no routing passes, no optimiser), default costs; an SMD Pad counts as escaped when a Track or Barrel of its net touches it without a violation (a Pad lying in a Pour of its net also counts); reference A reports this count itself at the end of its fanout stage, reference B was measured with the same rule._

Required outcome: on each board below, `route()` with `fanoutEnabled: true`, `routerEnabled: false`,
`optimizerEnabled: false` (everything else default) must raise `layoutStats().fanout.escaped` by at
least **N** over its value at load, where N is the "required gain" column (the smaller of the two
reference gains). R-1 (no added violation) and R-2 (held items untouched) hold as always, and every
item the stage adds belongs to the net of the Pad it escapes.

Notes:

- Fanout is a pre-pass: for each SMD Pad that is not yet connected it lays a short stub and, where
  the net must leave the Pad's Sheet, a Barrel; on a two-Sheet board whose nets can be reached on
  the Pad's own Sheet the stub may end on same-net copper without any Barrel, which is why the
  Barrel column can be 0 while the escape count rises.
- Reference A's escape count is the one it prints when its fanout stage ends; reference B's is
  `fanout.escaped` measured on the board after its fanout stage. Both start from the same board, so
  the "at load" value is shared.
- Boards with no SMD Pads and boards where a reference run failed are omitted.
