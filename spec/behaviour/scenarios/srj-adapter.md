# Scenario: the SimpleRouteJson adapter (routeSrj)

_generated by running one reference autorouter as a sealed program on the four J802 SimpleRouteJson
boards with a 60 s routing budget, observing the routed document's public shape and the reported
completion/violation/pair figures; the six-layer boards were run under the context-net import
reading they require (spec/formats/srj.md J-25)._

`routeSrj` takes a SimpleRouteJson problem (millimetres) and returns the same object with routed
copper attached (`spec/formats/srj.md`, `spec/api/contract.md`). The observable outcomes below
are what an external caller can check on the output alone.

## Required outcomes

- **No axis flip, millimetres in and out.** An output `wire`/`via` coordinate is a millimetre
  value in the same frame as the input points; copper that reaches an input endpoint shares its
  coordinates (J-01, J-03).
- **The stack is preserved.** A `layerCount`-N input yields output copper only on the layer names
  `top`, `inner1`..`inner(N-2)`, `bottom`; nothing collapses to two layers (J-10).
- **Required links are the declared endpoints only.** Each `connections` entry contributes
  `max(0, points − 1)` required links; net-owned pre-existing copper adds none (J-22, Q-68). On
  every J802 board this is 15 required links, not one per copper fragment.
- **No Violation is added.** `violationsAdded` is 0 on every board at every setting (R-1); all
  four J802 boards also load with 0 Violations (J-15's window reading of `bounds`).
- **Faithful or refused.** An obstacle shape the adapter cannot represent, a non-positive via
  size, or a keepout/unmatched-owner obstacle covering a declared endpoint makes `routeSrj`
  return `ok: false` listing every such conflict, rather than silently altering geometry
  (J-24..J-26).
- **One output record per physical copper item.** Each routed Track is one `pcb_trace` of `wire`
  steps; each via is one `pcb_trace` of a single `via` step; separate records never imply a join
  (J-41..J-43).
- **Every declared pair is measured.** For each `differentialPairs` entry the output reports both
  members' routed lengths, the skew, and whether it is within tolerance; coupling is not required
  and is not performed (J-32, J-44).

## Observed figures (sealed reference, `default`, 60 s budget)

| Board | Sheets | Required connections | Complete | Incomplete after | Violations before | Violations added | Import |
|---|---|---|---|---|---|---|---|
| `b223-j802.srj.json` | 2 | 15 | 12 | 3 | 0 | 0 | direct |
| `b223-j802-six-layer.srj.json` | 6 | 15 | 0 (budget) | 15 | 0 | 0 | needs context-net reading |
| `b223-j802-six-layer-v2.srj.json` | 6 | 15 | 9 | 6 | 0 | 0 | needs context-net reading |
| `b223-j802-six-layer-v3.srj.json` | 6 | 15 | 9 | 6 | 0 | 0 | needs context-net reading |

`v2` and `v3` are byte-identical inputs. Completion is via-dependent: most links join endpoints on
different Sheets, so the numbers rise once the barrel-aware search (I5) lands, while
`violationsAdded` stays 0. Differential-pair skews on the two-layer board, members routed
independently: `D0` 13.224 mm, `D1` one member unrouted, `C` 0.110 mm, `D2` 0.122 mm, `D3`
13.274 mm (tolerance 0.15 mm) -- so meeting tolerance is incidental without coupling, and the
`srj-*` cases hold the per-pair skew figures as advisory.
