# Scenario: detailed routing closes the completion gap on dense boards

_generated by running both reference implementations as sealed programs on each board under a
generous routing budget (up to 500 passes and a 300 s wall-clock budget per run; reference A given
8 worker threads, reference B allowed up to 30 stagnant passes) and measuring the resulting Layout
under the spec's connectivity and DRC rules; the best (lowest incomplete-after with **no added
Violation**) of the runs is reported per reference. The per-board numbers, their budgets and which
reference reaches each are recorded in `spec/acceptance/reference/<board>.bound.json` and
`<board>.bound-fanout.json`; the SimpleRouteJson boards are in `b223-j802*.srj.bound.json`._

These are the completion targets the M9 detailed router must reach and the invariants it must keep
while reaching them. They are outcome-only: they state what must be true of the Layout and the
`RouteReport` afterwards, never how the router gets there. The connectivity clauses they restate are
`rules/connectivity.md` K-17..K-19; R-1 and R-2 of `spec/api/contract.md` hold as always.

## Required outcome

For each board below, `route()` with the stated profile must leave at most the "target
incomplete-after" connections unrealised, add **no** Violation (R-1), and leave every `held`,
`locked` and Prior-copper item unchanged (R-2, K-18). The target is the best a sealed reference
reaches under the generous budget above; where the target is marked **reachable-clean** at least one
reference reaches it with no added Violation, so it is a hard bound in the matching case; where it is
marked **advisory** the completion depends on a capability (attaching to Prior copper, K-16) a coarse
router lacks, and the case bound is non-gating with the observed number recorded.

## Invariants the detailed stage must keep (K-17..K-19, restated per board)

- **No added Violation (R-1, K-17).** On every board above, `violationsAdded` is 0 whether the
  detailed stage is on or off. `cm5-carrier.dsn` and `Issue558-dev-board.dsn` carry pre-existing
  different-net Violations (25 and 2); these are preserved exactly and none is added.
- **Held, locked and Prior copper never move (R-2, K-18).** A fingerprint of every Pad, Pour, Fence,
  Rim, `held` file wire and Prior-copper item — its net, position and shape — is identical before
  and after routing, and identical between a run with the detailed stage off and one with it on. On
  `cm5-carrier.dsn` that fingerprint covers 980 such items; on `Issue730-DAC2020_bm11.dsn`, 234; on
  `Issue034-Green14SegLED.dsn`, 895. Each was observed unchanged across the paired runs.
- **Only completes, never regresses (K-19).** Turning the detailed stage on never lowers `completed`
  and never turns a complete connection incomplete on any board here; the completions it adds are
  recorded per board in `shove.md`.

## Notes

- "Reachable-clean" means a sealed reference reaches the target with no added Violation; a run that
  reaches a lower incomplete-after only by adding Violations (reference B on `Issue034-Green14SegLED`
  and on `Issue730-DAC2020_bm11` under fanout) is **not** admissible and is not the target.
- Reference A honours any job timeout the board file itself specifies; on `Issue508-DAC2020_bm01.dsn`
  that caps its run at 60 s, which is why its wall clock stops below the 300 s budget.
- The fanout-profile boards need the fanout pre-pass (`fanoutEnabled: true`) to escape their SMD
  Pads before routing; see `fanout.md` for the escape counts and `rules/connectivity.md` for how the
  detailed stage then joins the escaped Pads.
