# Task S2 — rules semantics, parse summaries, glossary review

Role: spec-curator. Write set: `spec/rules/`, `spec/acceptance/parse/`, `spec/glossary.md`
(additions only), `spec/acceptance/cases/parse-summary-*.json`.

## Deliverables

1. `spec/rules/clearance.md` — clearance Kinds (classes) and the SpacingTable: default Kind,
   how `rule`/`layer_rule`/`class`/`class_class` and `.rules` files populate it, pair types
   (`smd_smd`, `smd_via`, `via_via`, `pin_pin`, `smd_pin`, `wire_*`, `area_*`, `default`, …) and
   which item categories map to which, per-Sheet overrides, symmetry, unit rounding stated as an
   observable ("a clearance of N in a file with resolution R yields spacing S LU"), and the
   largest-value rule used to size queries. Clauses `C-nn`.
2. `spec/rules/nets.md` — nets, pins, subnets (`fromto`/`order`), NetGroups (`class`): width,
   Kind, via rule, usable Sheets (`use_layer`), `circuit` length limits (if any board uses them),
   `ignoreNetGroups` semantics, empty/duplicate net names.
3. `spec/rules/vias.md` — via rules (`via_rule`, `use_via`, structure `via` list) as ordered
   PadForm candidates; through/blind/buried by Sheet span; `attach`; fixed vias in `wiring` and
   their `type`; what "vias disabled" means.
4. `spec/rules/keepouts.md` — Fence kinds (`keepout`, `via_keepout`, `wire_keepout`,
   `place_keepout`), Sheet scoping (named, `signal`, `pcb`), net-owned copper vs obstacles,
   degenerate keepouts.
5. `spec/rules/layers.md` — signal vs plane (`type power`) Sheets; inactive Sheets (from
   settings or `use_layer`); plane Sheets block other-net Tracks and Barrels; layer count is
   always the file's; preferred direction per Sheet.
6. `spec/rules/connectivity.md` — what connects: Track end inside same-net Pad copper; Track end
   on another same-net Track; Barrel/through Pad across Sheets; Pour joins same-net items it
   overlaps; plane Sheets join every same-net Barrel/through Pad reaching them. **Record the pour
   ruling**: the references disagree on whether a copper pour connects its net; the spec follows
   the CAD tool's DRC (a pour connects). Give both observed numbers for the board(s) affected.
   Define `connections.maximum` and `incomplete`.
7. `spec/rules/drc.md` — the violation definition (spacing per pair type per Sheet; Rim/copper-to-
   edge; hole clearance; Fences), pair dedup, the "router never adds a violation" invariant,
   `strictDrc` semantics, and the load-time expected numbers for the boards with CAD-tool DRC
   reports in the corpus.
8. `spec/acceptance/parse/<board>.json` for every board in the corpus, per
   `spec/acceptance/schema/parse-summary.schema.json`, generated by running **both** references'
   readers and reconciling; any disagreement becomes a `D-nn` entry you hand to S1 (write it into
   `spec/formats/dsn-dialects.md` under a "from S2" heading) and the summary records the ruling.
9. `spec/acceptance/cases/parse-summary-*.json` — one `parse` case per board with
   `expect.summaryEquals` (fast tier for boards < 300 KB, else slow).
10. Review `spec/glossary.md` and add missing terms (additions only).

## Rules of writing
Behaviour only. Never name reference classes, files, or functions. `bun run spec:lint` must be
clean before you commit (spec-curator trailers).
